# Dan Flashes

> Complicated shirts. Complicated prices.

An e-commerce storefront for Dan Flashes, where every shirt is vibrant and the price goes up with the
complexity of its pattern. It's a parody built to learn spec-driven development with
[GitHub Spec Kit](https://github.com/github/spec-kit). There are no real payments: every card is
fake and every dollar is pretend.

**Stack**:
- Next.js 16 (App Router, Cache Components), TypeScript, Tailwind CSS 4
- SQLite via Drizzle ORM, with exact-decimal money via big.js
- Vitest + Playwright

## Quick start

Requires Node 22+.

```bash
npm install
npm run db:reset        # creates data/danflashes.db: demo catalog + demo@danflashes.local / password123
                        # ($10,000 of Flash Credit and a $75.00 daily per diem).
                        # After pulling, use db:migrate instead: it keeps your data. Then db:seed adds
                        # anything new in the demo catalog (like the add-ons), skipping what exists.
npm run dev             # http://localhost:3000
```

Test card: **4242 4242 4242 4242**, any future expiry (e.g. 12/29), any 3-digit CVC.

## Managing the store

All product data lives in SQLite, not in code. The owner manages it in **Dan's Office**, the
console at `/admin` (008):

```bash
npm run db:reset                          # also creates the demo owner (DEMO_OWNER in scripts/seed-data.ts)
npm run admin:grant -- you@example.com    # make an existing account an admin; admin:revoke undoes it
npm run catalog:audit                     # the catalog check, also on the console's Pricing page
```

Sign in as an admin and a **Back office** link appears in the store header. Anyone else gets the
store's ordinary 404 at every `/admin` address, and every console change is checked again on the
server. A confirmation ("Saved. That was a good decision, Dan.") goes away by itself after a few
seconds, so the next save shows it again; a refusal stays until it's fixed. Only the command line can make or unmake an admin. After pulling 008, run
`npm run db:migrate` (0011), then `npm run admin:grant -- <your email>`. The console is deliberately calm: none
of the tactics run there, nothing flashes, and every page has a motivational poster.

- **Shirts**: each one's score, tier, MSRP and final price. Create one, edit it with a live preview,
  rest it (deactivate) and bring it back. There's no delete, and the URL name is fixed once created.
- **Generate** (007, **Generate one** on Shirts): pick a target score (type it, or drag the slider,
  spaced like the dial) and a style, Shuffle until you like one, name it, and save it. It rests
  until you put it on the floor. Its art goes in the media library, and its score is the one
  counted from its pattern; change it like any other shirt's (the art stays as drawn). The tiers
  start at 10, 25, 45, 70 and 100, and the hand-drawn catalog runs from 2 to 130, so 0–150 is where
  shirts live; everything above is for the dial's joke.
- **Review shopper creations** (007, on Shirts): the shirts shoppers made at the dial, each with
  its maker. **Put it into mass production** and it's an ordinary shirt in the listing, for
  everyone, with every tactic and no surcharge. **Make it one of a kind again** and only its maker
  can buy it. The shirts list marks generated shirts ("Generated by you", "Made by a shopper",
  "mass-produced") and filters by where they came from.
- **Pricing**: price against score, every pair priced against the complexity order, how far your
  own prices sit from the MSRP, and the catalog audit's problems with links to fix them.
- **Media**: upload a PNG, JPEG or WebP at least 2,000 px on its longest side, or an SVG with no
  scripts or outside references, up to 15 MB. Uploads are kept in `MEDIA_UPLOADS_DIR` (default:
  `uploads/` beside the database file) and served from `/media/uploads/…`. Attach pictures to a
  shirt and order them (the first is the main one). Only a picture nothing uses can be removed.
- **Tiers**: saved as one set, with a preview of the shirts that change tier.
- **Add-ons**: create, edit, retire, restore and reorder.
- **Settings**: every tactic switch in one click, the MSRP dials with a before-and-after preview,
  the Flash Credit top-up amounts, the media base URL, the placeholder picture, and the Uniquity
  Surcharge's amount.
- **Customers and orders**: look only, except one thing: **grant** a customer Flash Credit. It's a
  ledger entry, recorded once per form, spent like a top-up; the shopper sees "A gift from Dan".

`npm run db:studio` (Drizzle Studio) is still there for developers. The owner no longer needs it.

- **Complexity score** (`shirts.complexity`) is owner-only and never shown to shoppers. It sets
  the shirt's tier badge and its MSRP.
- **MSRP** = base price + price per point × score, exact to the cent (010: a straight line, $50.00
  + $25.00 a point by default). The two dials live in `store_settings`, and Dan tunes them in
  Settings.
- **Gentler pricing** (010). After pulling, run `npm run db:migrate` (0014). It backs the database
  up first, then puts the store on the default line and clears every final price Dan set himself,
  so every shirt sells at its new MSRP. Orders keep what they charged. The old prices are in that
  backup (`npm run db:restore`) if you want them back.
- **Final price** is `shirts.final_price_usd` if you set one, otherwise the MSRP.
- **How complicated can it get?** (007, `/how-complicated`, linked from the home page and from
  under the shirt listing's filters). A dial from BLAND to "too complicated to price". The badge
  and price follow the slider at once; the art and the address bar follow when it settles, and
  that link reopens the exact shirt. Shuffle and the style toggle draw another pattern at the same
  level. A pattern's count is its score: one point for every 10 points it's drawn with, plus 5 for
  each extra color, plus 10 for each extra layer, so a generated shirt is about as busy as a
  hand-drawn one at the same score. The dial's top is a fixed score of 10,249 (where the old
  exponential ran out of numbers), and no score ever reaches the browser.
- **One of a kind** (007). **Make it mine** needs an account (a guest signs in and comes back to
  the same setting). It turns the setting into a real shirt on its own page, made to order for him:
  only he can buy it, as many as he likes, and the same setting always lands on the same shirt.
  Anyone else with the link sees it's somebody else's, with no way to buy it. It never shows in the
  listing, the home page, pop-ups or suggestions, and its page has no fake crowd. Its stock line
  says it's made to order. Each one pays the **Uniquity Surcharge™** on its own line, once per
  shirt, until Dan mass-produces it. After pulling 007, run `npm run db:migrate` (0012 and 0013;
  0013 makes each shopper-made shirt's first buyer its maker).
- **Tiers** (`complexity_tiers`) can be renamed, restyled, and re-ranged. The tier starting at 0 is
  BLAND.
- **Never delete a shirt.** Rest it in the console (`status` = `inactive`). Shirts that have been
  ordered can't be deleted, and a rested shirt's page stays up (marked retired) for order history.
- **Images** live in `public/media/` and are referenced by relative key. To move them to a CDN,
  change the media base URL in Settings (`store_settings.media_base_url`).
- **Revenue streams** are connected by shoppers on their account page and feed Flash Credit. A
  "Recurring top-off" pays on its own interval (for a demo, connect one that tops off every 1
  minute). "Just once" is applied immediately and is final. "Whenever I want" pays each time he hits
  Cash in. Payments that came due are credited whenever his money is shown, exactly once each.
- **Checkout splits the bill.** "Apply my Flash Credit" covers what it can. He confirms putting the
  rest on a card, and Remove puts the whole total back on the card.
- **Add-ons** (`add_ons`) are owner data: a name, a pitch, a decline line, a flat price per order,
  `active`, and `position`. Edit them in the console. Retire one there, and never delete one:
  past orders keep their own copy of what was bought (`order_add_ons`), at the price paid.
- **Manipulation switches** (constitution IV). Each tactic is its own `store_settings` column. Flip it
  in the console's Settings, one click each; the store follows on the next page load.

  | Column | Default | When on |
  |---|---|---|
  | `checkout_gate` | on | Guests can build a cart but must sign in to check out |
  | `bland_shaming` | on | BLAND shirts can't be in a cart at all. Add to Cart opens the endless "You sure about that?" loop, the store refuses bland adds and raises, sign-in merges leave bland lines behind, and lines already in a cart are pulled with a notice. |
  | `confirmshaming` | on | Decline buttons make him feel it: "Yes, I'd rather blend in", "Remove (and lose your edge)", "Sign out (go back to being normal)", "Disconnect (and settle for less)" |
  | `per_diem_drain` | on | A gauge in the corner counts his per diem down with every order, by any payment method, and throws a party at $0. Every order spends the per diem first, then the oldest stream money. Each stream shows what's left. Every stream that runs dry pops a "[Stream]: GONE" trophy in the same corner, above the gauge, and each has an (x) to clear it until that stream pays in and drains again. While it's off, the gauge, the amounts left and the trophies are hidden, and orders placed then never earn one. |
  | `drain_jokes` | on | Each GONE in the corner also says what he did: "You spent your kid's college fund on shirts." A look, not a tactic: it only matters while `per_diem_drain` is on. |
  | `fake_scarcity` | on | Every shirt card, shirt page and cart line says "Only 1 left!" (bland shirts: "Plenty left. Nobody wants these."). Every add adds "Oh wait, we found another one!", a cart line holding more than one says "You're lucky, we actually found a few more!", and once he's bought a shirt it says "Just kidding, we actually found another one! One more left!" It never limits what he can buy. |
  | `countdown_timers` | on | One 10-minute clock per browser, down to the millisecond: "This price won't last." beside the price, and "Your shirts are reserved for" on the cart and checkout. At zero it quietly starts over. Nothing ever expires or changes price. |
  | `social_proof` | on | Shirt pages say how many people are looking (3–40, drifting; 0 for bland shirts) and which fake coworker just bought it. Fake purchase pop-ups come every 20–40 seconds on every page, each with an (x): bottom-right on wider screens, under the header on phones. No real shopper or order ever appears. |
  | `pre_checked_add_ons` | on | Checkout arrives with every offered add-on already ticked (Pattern Protection Plan™, Complexity Insurance, …), every time it opens. The total includes them; he has to untick each one, and while confirmshaming is on Dan has a line for every untick. Each add-on bought is its own line on the order. |
  | `roach_motel` | on | Adding takes one click. Removing a line, or lowering its quantity, asks "Are you sure?" and then "Are you sure sure?". The yes buttons follow confirmshaming. Removals the store makes itself never ask. |
  | `flash_mode` | on | Flash Mode (constitution V), the strobe that the shopper's **Extreme Awesomeness** button turns on. Backgrounds and borders step through the store's colors, at most 2.5 times a second. Prices, tier badges, Add to Cart and money rows never change, and no text color ever does. |
  | `pipes_background` | on | Also turned on by Extreme Awesomeness: the old office "3D Pipes" screensaver grows behind every page on a black field, in its classic colors, and clears when the screen fills. It never covers or blocks anything. |
  | `nosy_sign_up` | on | Sign-up asks for far too much after the real fields: Social Security Number, mother's maiden name, blood type, current medications and more, each marked "Required". They're props: unnamed, outside the form, no autofill. Nothing typed into them is ever sent, stored or logged. Blanks get one line from Dan ("He'll allow it."), and the next press signs up. Email and password carry `**`: "Actually required." After pulling 009, run `npm run db:migrate` (0010). |
  | `pattern_generator` | on | The "How complicated can it get?" dial and its calls to action. Off: the dial and its art are the store's 404, and nobody can make a shirt there. Shirts already made stay as they are, and Dan's generator in the console keeps working. |
  | `uniquity_surcharge` | on | Every one-of-a-kind (shopper-made, not mass-produced) shirt pays a flat Uniquity Surcharge™, once per shirt, on its own line in the cart, at checkout, on the receipt and in order history. The amount is `uniquity_surcharge_usd` ($499.99), set in Settings. Orders keep what they were charged; a changed amount makes checkout ask him to look again. |

  **Extreme Awesomeness** is the shopper's own toggle, in the header of every page. It starts off,
  applies at once, and his browser remembers it (every tab, later visits). It's never sent to the
  store or saved to his account, so other browsers keep their own choice. With both switches above
  off, the button is hidden. After pulling 006, run `npm run db:migrate` for the two switches (0009).

## Scripts

| Command | What it does |
|---|---|
| `npm run dev` | Dev server on :3000 |
| `npm run verify` | **The one-glance health check**: format, lint, type check, unit and integration tests (≥ 90% coverage), then e2e tests on a production build (desktop + phone) |
| `npm test` | Unit and integration tests only |
| `npm run test:e2e` | Playwright end-to-end tests (first time: `npx playwright install chromium`) |
| `npm run format` | Prettier |
| `npm run db:migrate` | Back up, then apply migrations |
| `npm run db:backup` / `db:restore -- <file>` | Timestamped backups in `backups/`; restoring makes a safety backup first |
| `npm run db:reset` | Back up, then rebuild and reseed the database (catalog and demo shopper) |
| `npm run db:seed` / `db:seed-demo` | Demo catalog / demo shopper and owner (both idempotent) |
| `npm run admin:grant -- <email>` / `admin:revoke -- <email>` | Make an account the owner, or stop it being one (the only way) |
| `npm run catalog:audit` | The catalog check: errors exit 1, warnings exit 0 |
| `npm run art:generate` | Regenerate the placeholder shirt art (it shares the pattern generator's shirt silhouettes and palettes) |

The e2e suite builds into `.next-e2e/` and uses `data/e2e.db`, so it can run while your own
`npm run dev` is running.

### When a page 500s

Shoppers only ever see the 500 page. The **terminal running the server** explains what broke, with
the command that fixes it, in lines starting `[Dan Flashes]`. The browser's dev console also points
there. Usually it's one of these:
- **"…migrations behind the code…"**: you pulled a change that alters the database. Run
  `npm run db:migrate`, which keeps your data. A running dev server picks the change up on its own.
- **"No database…" or "Store settings are missing"**: run `npm run db:reset`.

## How this repo is organized

| Path | What it is |
|---|---|
| `.specify/memory/constitution.md` | The project's governing principles. Every spec and plan is checked against it. |
| `specs/NNN-feature-name/` | One folder per feature: `spec.md` (what & why), `plan.md` (how), `research.md`, `data-model.md`, `contracts/`, `quickstart.md`, `tasks.md` |
| `ROADMAP.md` | Features after 001: brand pages, per diem, the urgency engine, Flash Mode, the admin console, and more |
| `src/lib/` | Framework-free domain logic (money, pricing, cart, checkout, ledger, auth). Fully tested. |
| `src/actions/` | Thin `"use server"` adapters over `src/lib/actions/` |
| `src/app/` | Pages. Database reads happen at request time inside `<Suspense>`. |
| `scripts/` | Database, seed, audit, and art utilities |
| `tests/` | `unit/`, `integration/` (temp SQLite per file), `e2e/` (Playwright) |

See [`specs/001-core-storefront/quickstart.md`](specs/001-core-storefront/quickstart.md) for the
full validation walkthrough and performance results.

## Spec-driven workflow

```text
/speckit-constitution  → once per project
/speckit-specify       → per feature: what & why, no tech
/speckit-clarify       → optional: de-risk ambiguity before planning
/speckit-plan          → tech stack, architecture, data model
/speckit-checklist     → optional: "unit tests for English"
/speckit-tasks         → ordered, dependency-aware task list
/speckit-analyze       → cross-artifact consistency check (required before implementing money features)
/speckit-implement     → build it
/speckit-converge      → repeat implement → converge until Converged
```
